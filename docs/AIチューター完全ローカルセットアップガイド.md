# AIチューター完全ローカルセットアップガイド

AI チューターを、Ollama と ChromaDB を使って学内のマシンだけで動かす手順です。外部の API やキーは使いません。インターネット接続が必要なのは、モデルとパッケージを取得するときだけです。

## 構成

| 部品 | 役割 | 必須 |
|------|------|------|
| Ollama | チャットモデル（回答生成）と埋め込みモデル（検索用ベクトル）を動かす | 必須 |
| ChromaDB | `content/knowledge/` の Markdown を索引にして検索する | 任意 |
| メインサーバー | `/tutor` 画面と `/tutor/*` API を提供する | 必須 |

ChromaDB がなくてもチューターは動きます。その場合は知識ベースを検索せず、LLM だけで回答します。

## 1. Ollama とモデル

[ローカルLLMセットアップガイド](./ローカルLLMセットアップガイド.md) の 1〜2 に従って、Ollama をインストールし、次の 2 つのモデルを取得します。

```powershell
ollama pull hf.co/elyza/Llama-3-ELYZA-JP-8B-GGUF:latest
ollama create elyza-jp:8b -f config/ollama/Modelfile.elyza
ollama pull bge-m3
```

## 2. ChromaDB（知識ベース検索を使う場合）

Python の Chroma サーバーを、メインサーバーとは別のターミナルで起動します。

```powershell
pip install chromadb
chroma run --path ./storage/chroma
```

プロジェクトルートで実行します。待ち受けは `http://localhost:8000` です。別の URL にする場合は `CHROMA_URL` を設定します。

メインサーバーより先に起動してください。メインサーバーは Chroma への接続に一度失敗すると、再起動するまで接続し直しません。

## 3. メインサーバーの起動

```powershell
npm install
npm start
```

環境変数は既定のままで動きます。変える場合は [ローカルLLMセットアップガイド](./ローカルLLMセットアップガイド.md) の「3. 環境変数」を参照してください。

## 4. 知識ベースの構築

知識ベースは、サーバー起動時ではなく、最初にチューターが使われたときに作られます。ログインして `http://localhost:3333/tutor` を開くと構築が始まり、ログに次のように出ます。

```text
✅ ローカル埋め込みモデル（Ollama）を初期化しました: bge-m3 at http://localhost:11434
✅ ChromaDBコレクション準備完了
📚 知識ベースを読み込み中...
📝 XX個のチャンクを生成しました
🔄 埋め込みベクトルを生成中...
✅ 知識ベースのインデックス化が完了しました
```

2 回目以降の起動では、既存の索引をそのまま使います（`📚 既存の知識ベースが見つかりました（XX件）`）。

画面のステータスは 2 秒ごとに更新され、次の表示になれば準備完了です。

```text
準備完了 (ローカルLLM: elyza-jp:8b, 知識ベース: XX件)
```

### 索引の作り方

| 項目 | 内容 |
|------|------|
| 対象 | `content/knowledge/*.md`。ただし問題別ヒント集（`easy1.md`〜`hard2.md`）は除く |
| 分割 | Markdown の見出しごとに分け、長い節は 400 文字（重なり 40 文字）で再分割 |
| 除外する節 | 「ローカルLLM回答方針」「安全な回答方針」「情報開示の注意」 |
| 保存先 | Chroma のコレクション `ctf_knowledge_v3`（データは `storage/chroma/`） |
| 検索 | 質問ごとに上位 5 件を回答の参考にする |

### 問題別ヒント集

`content/knowledge/easy1.md`〜`hard2.md` は索引に入れず、学習者がその問題を開いてチューターに質問したときだけ使います。ファイル名はカテゴリー名を小文字にしたもの（`Easy1` → `easy1.md`）で、問題ごとに `## <問題ID>` の節を書きます。ヒントは上の行ほど浅くし、チューターは会話が進むごとに一段ずつ使います。

### 知識ベースを作り直す

`content/knowledge/` を編集したり、埋め込みモデルを変えたりしたときは、索引を作り直します。ログインした状態で次のどちらかを開きます。

- ブラウザで `http://localhost:3333/tutor/rebuild`
- `POST /tutor/rebuild`

作り直しのときは、たまっていたチューターの Q&A ログ（`storage/tutor_qa_pending.jsonl`）も `docs/tutor-qa-<日時>.json` に書き出されます。

## 使い方

| 操作 | 内容 |
|------|------|
| 質問する | `/tutor` で質問を入力して送信する。回答はストリーミングで表示される |
| 問題から開く | 問題のモーダルの「AIチューター」ボタンから開くと、`/tutor?category=<カテゴリー>&questionId=<問題ID>` でその問題の情報とヒント集を踏まえて回答する |
| 会話履歴 | ユーザーごとにサーバーのメモリで直近 20 件を保持する。消去は `/tutor/clear`。サーバーを再起動すると消える |
| 順番待ち | 回答生成は 1 件ずつ。混んでいるときは待ち行列の順番が表示される |

回答には次の後処理がかかります。

- フラグ文字列を伏せる
- 参照資料にない URL を取り除く
- 指示文のオウム返しや同じ文の繰り返しを取り除く
- 英語の拒否応答を日本語にする
- 6,000 文字を超える回答は切り詰める

## トラブルシューティング

### ステータスが「⚠️ Ollamaが起動していません」

Ollama に接続できていません。`ollama list` が動くか確認し、Ollama を起動します。

### ステータスが「埋め込みモデルを初期化中...」から進まない

次のどれかです。

- Chroma が起動していない、または `CHROMA_URL` が違う：「2. ChromaDB」の手順で起動し、メインサーバーを再起動する
- 埋め込みモデルがない：`ollama pull bge-m3`（`OLLAMA_EMBEDDING_MODEL` を変えた場合はそのモデル）

Chroma なしでも質問には回答します。その場合は知識ベースを検索しません。

### 知識ベースを直したのに回答に反映されない

既存の索引が残っているためです。「知識ベースを作り直す」の手順で作り直します。

### 応答が遅い

- 最初の回答はモデルの読み込みに時間がかかる。2 回目以降は速くなる
- 他の人の質問を生成中なら、順番待ちになる
- 改善しない場合は [ローカルLLMセットアップガイド](./ローカルLLMセットアップガイド.md) の「応答が遅い、またはメモリが足りない」を参照する
