XSS攻撃の仕組みと対策

XSSとは

XSSとは、Cross-Site Scriptingの略で、Webサイトに悪意のあるスクリプトを埋め込み、 そのページを見た利用者のブラウザ上で実行させる攻撃です。

本来、Webサイトはユーザーが入力した文字を「文字列」として表示するべきですが、 処理が不十分だと、入力内容がHTMLやJavaScriptとして解釈されてしまうことがあります。

XSS攻撃の基本的な仕組み

例えば、掲示板に次のような投稿ができるとします。

こんにちは！

しかし、攻撃者が以下のような内容を投稿した場合を考えます。 

<script>alert("XSS")</script>

サイト側がこの入力をそのままHTMLとして表示してしまうと、 ブラウザはこれをJavaScriptとして実行してしまいます。

注意： XSSでは、攻撃者のコードが「被害者のブラウザ上」で実行される点が重要です。

XSSで起こり得る被害

  • Cookieやセッション情報の盗難
  • 偽のログイン画面の表示
  • ページ内容の改ざん
  • ユーザーになりすました操作
  • 別の悪意あるサイトへの誘導

XSSの主な種類

1. 蓄積型XSS

攻撃コードが掲示板やプロフィール欄などに保存され、 そのページを見た他のユーザーに対して実行されるタイプです。

2. 反射型XSS

URLのパラメータなどに含まれた攻撃コードが、 サーバーのレスポンスにそのまま反映されて実行されるタイプです。

3. DOM Based XSS

サーバーではなく、ブラウザ側のJavaScript処理に問題があり、 DOM操作によって攻撃コードが実行されるタイプです。

XSSが発生する原因

XSSの主な原因は、ユーザー入力を適切に処理せず、 HTMLとしてそのまま出力してしまうことです。 

投稿内容: <script>alert("XSS")</script>

このように表示されると、ブラウザは <script>タグを本物のJavaScriptとして解釈してしまいます。

XSSへの対策

1. エスケープ処理を行う

ユーザー入力に含まれる特殊文字を、HTMLとして解釈されない形に変換します。

文字 変換後
< &lt;
> &gt;
" &quot;
' &#39;
& &amp;

2. innerHTMLの使用を避ける

JavaScriptで画面に文字を表示する場合、 innerHTMLではなくtextContentを使うことで、 入力内容をHTMLではなく文字列として扱えます。 

// 危険な例
element.innerHTML = userInput;

// 安全な例
element.textContent = userInput;

3. CookieにHttpOnly属性を付ける

CookieにHttpOnly属性を付けると、 JavaScriptからCookieを読み取れなくなります。 

Set-Cookie: sessionid=abc123; HttpOnly; Secure; SameSite=Lax

4. CSPを設定する

CSP、Content Security Policyを設定することで、 実行できるスクリプトの読み込み元を制限できます。 

Content-Security-Policy: default-src 'self'; script-src 'self';
ポイント： XSS対策では、「入力を信用しない」「出力時にエスケープする」 という考え方が重要です。

まとめ

XSSは、ユーザー入力がHTMLやJavaScriptとして実行されてしまうことで発生します。 攻撃が成功すると、Cookieの盗難やページ改ざんなどの被害につながる可能性があります。

対策としては、エスケープ処理、危険なDOM操作の回避、 Cookieの保護、CSPの設定などが有効です。
