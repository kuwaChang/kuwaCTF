# OSINT ナレッジ

## 目的
この文書は、CTFのOSINTカテゴリに関する質問へローカルLLMが一貫して答えるための参照用インデックスである。  
個別の質問に対する暗記型Q&Aではなく、OSINT問題で共通して使う考え方、調査手順、代表ツール、検証観点、注意点を体系的にまとめる。

---

## OSINTとは
OSINTは **Open Source Intelligence** の略で、公開されている情報を収集・整理・検証して、目的の情報を導き出す手法である。

CTFでは、次のような能力を問う問題が多い。

- 画像から場所・施設・会社・日時を特定する
- SNSアカウントやユーザー名の関連情報を追跡する
- ドメイン、DNS、WHOIS、Wayback Machineから過去情報を調べる
- 画像検索や地図、公開データベースを使って根拠を積み上げる
- 得られた情報の信頼性を検証する

OSINTでは「検索できること」よりも、**情報を疑い、複数の根拠で確認すること** が重要である。

---

## 基本的な調査フロー

### 1. 与えられた情報を整理する
最初に、画像・文章・ファイル名・URL・座標・ユーザー名など、問題文に含まれる情報を分解する。

確認する観点:

- 人名、地名、施設名、会社名
- 看板、ロゴ、制服、車両、機体、建物
- 言語、通貨、道路標識、電話番号
- ファイル名、拡張子、EXIF、作成日時
- URL、ドメイン、サブドメイン
- 座標、時刻、天候、影の向き

### 2. 画像や文字情報から検索キーワードを作る
画像内の特徴や文章中の固有名詞を検索語に変換する。

例:

- 「ホヌ柄 飛行機」
- 「Honu aircraft airline」
- 「airport official Wi-Fi SSID Hawaii」
- 「蛇 杖 医療 シンボル」
- 「座標 60.8841988 101.8857172」

### 3. 複数の検索手段を使う
1つの検索方法だけに頼らない。

代表的な手段:

- Google検索
- Google画像検索
- Google Maps / Street View
- Bing画像検索
- Yandex画像検索
- SNS検索
- WHOIS
- DNS lookup
- Wayback Machine
- Google Patents
- GitHub検索

### 4. 情報を検証する
検索結果をそのまま信じず、公式サイト・複数ソース・日時・文脈を確認する。

確認すること:

- 公式情報か
- 複数の独立した情報源で一致するか
- 古い情報ではないか
- 画像や文章が別の文脈で再利用されていないか
- 位置・日時・名称に矛盾がないか

### 5. フラグ形式に合わせて答える
CTFでは、調査結果をそのまま答えるのではなく、指定された形式に整形することが多い。

例:

- `ctf{ssid_name}`
- `FLAG{company_name}`
- `ctf{YYYY-MM-DD}`
- 空白を `_` に変える
- 大文字・小文字を指定に合わせる

## 画像OSINTの見るべきポイント

画像から場所や情報を特定する場合、最初に以下を見る。

### 文字情報
看板、標識、ポスター、店名、駅名、空港名、ナンバープレート、制服の文字など。

### 視覚的特徴
建物の形、道路、山、海、橋、電柱、車線、信号、広告、ロゴ、機体塗装など。

### 環境情報
天気、植生、道路標識の形式、言語、車の進行方向、建築様式など。

### メタデータ
EXIFが残っている場合、GPS、撮影日時、カメラ機種、編集ソフトなどを確認する。

代表ツール:

```bash
exiftool image.jpg
file image.jpg
strings image.jpg
```

## EXIFとメタデータ

EXIFから取得できる代表的な情報:

- 撮影日時
- GPS座標
- カメラ機種
- レンズ情報
- 画像サイズ
- 編集ソフト
- サムネイル
- タイムゾーン情報

ただし、SNSやメッセージアプリにアップロードされた画像はEXIFが削除されることが多い。

EXIFがない場合でも、以下の調査は可能。

- 画像検索
- 文字・ロゴ・看板の読み取り
- 地形や建物の比較
- SNS上の同一画像検索
- 撮影地点候補の地図確認

## リバースイメージサーチ

画像そのもの、または画像の一部を使って類似画像を検索する方法。

代表サービス:

- Google Lens
- Google画像検索
- Bing Visual Search
- Yandex Images
- TinEye

使い方のポイント:

1. 画像全体で検索する
2. 特徴的なロゴ・建物・看板だけを切り抜いて検索する
3. 別の検索エンジンでも試す
4. 出典ページの日付や説明文を確認する
5. 画像の再利用や転載に注意する

## ユーザー名調査

ユーザー名しかない場合は、同じIDが他サービスで使われていないかを調べる。

調査例:

- `"username"`
- `"username" site:github.com`
- `"username" site:x.com`
- `"username" site:instagram.com`
- `"username" "email"`
- `"username" "CTF"`

見るべき情報:

- 同一アイコン
- 同じプロフィール文
- 同じリンク
- 投稿内容の一致
- GitHubやSNSの相互リンク
- メールアドレスやドメインの共通性

同姓同名や同一IDの別人がいる可能性があるため、複数の一致要素で判断する。

---

## ドメイン・DNS・WHOIS調査

ドメインから確認できる情報:

- 登録日
- レジストラ
- ネームサーバー
- DNSレコード
- サブドメイン
- IPアドレス
- 過去のWebページ
- 証明書履歴

代表コマンド:

```bash
whois example.com
dig example.com
dig NS example.com
dig MX example.com
dig TXT example.com
nslookup example.com
```

DNSレコードの例:

- A: IPv4アドレス
- AAAA: IPv6アドレス
- CNAME: 別名
- MX: メールサーバー
- TXT: SPF、検証情報など
- NS: ネームサーバー

## Wayback Machine

Wayback Machineは、過去のWebページを閲覧するために使う。

用途:

- 削除されたページの確認
- 過去の会社情報や連絡先の確認
- 古いrobots.txtの確認
- 古いソースコードやディレクトリ構造の確認
- 変更前の文言やリンクの確認

注意点:

- すべてのページが保存されているわけではない
- 動的ページは完全に再現されないことがある
- 保存日時と実際の更新日時は一致しない場合がある

## Google Patents

特許を調べるときに使う検索サービス。

調べられる情報:

- 発明者
- 出願人
- 出願日
- 公開日
- 特許番号
- 要約
- 図面
- 関連特許

検索例:

- 発明者名
- 会社名
- 技術キーワード
- 特許番号
- `"keyword" "inventor"`

CTFでは、特定の人物・会社・技術と特許を結びつける問題で使われることがある。

## 座標調査

座標が与えられた場合は、地図サービスで確認する。

見るべき情報:

- 国、地域、都市
- 周辺施設
- 道路や川
- 事件・事故・歴史的出来事
- 近くの建物や名称
- 座標の形式が正しいか

使うサービス:

- Google Maps
- OpenStreetMap
- Wikimapia
- GeoHack
- Wikipedia
- ニュース検索

座標は緯度・経度の順番が逆になっている可能性もある。

---

## 信頼性検証の観点

OSINTで重要なのは、見つけた情報が本当に正しいかを検証すること。

チェックポイント:

- 公式サイトか
- 一次情報か
- 複数ソースで一致するか
- 情報の日付は新しいか
- 画像・文章が転載ではないか
- 文脈が問題と一致しているか
- 地図、写真、説明が矛盾しないか
- フラグ形式に合っているか

信頼性が高い順の目安:

1. 公式サイト・公的機関
2. 企業や団体の公式SNS
3. 信頼できるニュース・論文・特許DB
4. 複数の独立した個人サイト
5. 未確認のSNS投稿や掲示板

---

## CTFでの注意点

- OSINTは攻撃ではなく公開情報の調査である
- 個人情報の不必要な収集を避ける
- 実在人物への接触は通常不要
- SNSアカウントへの迷惑行為をしない
- 問題のスコープ内で調査する
- 答えは必ず根拠とセットで考える

---

## ローカルLLM回答方針

ローカルLLMは、OSINT質問に答えるとき以下を優先する。

1. 調査対象を整理する
2. 代表的な調査手順を示す
3. 具体的な検索クエリ例を出す
4. 検証方法を必ず説明する
5. 不確かな情報は断定しない
6. CTF用途として安全な範囲で説明する

## 補足知識

## 重要な考え方（初心者向け）

### 1. まず全部出す
- strings
- exif
- file

### 2. 違和感を探す
- 不自然なデータ
- 変な文字列
- 拡張子と中身のズレ

### 3. 仮説 → 検証
- 「Base64っぽい」→ デコード
- 「zipっぽい」→ 解凍

## 最低限の初動テンプレ

1. `file` → ファイルの正体確認  
2. `strings` → 文字列抽出  
3. `exiftool` → メタデータ確認  
4. `binwalk` → 埋め込み探索

## OSINT / フォレンジック手順まとめ

### 1. 画像の逆引き検索

#### 使用ツール
- Google Images（画像検索）
- TinEye
- Yandex Images（建物・人物に強い）

#### 手順
1. 画像をアップロードして検索
2. 完全一致と類似画像を確認
3. 最も古い投稿（初出）を探す
4. 別角度の画像を収集する
5. 写っている要素（建物・看板など）を特定する

#### ポイント
- GoogleだけでなくYandexも使う
- 「最初にどこで出たか」を重視する

### 2. 位置特定（ジオロケーション）

#### 使用ツール
- Google Maps
- Google Street View
- GeoGuessr（練習用）

#### 手順
1. 画像からヒント抽出（言語・ナンバープレート・電柱・信号など）
2. 地域を仮決めする
3. Mapsで候補を探す
4. Street Viewで一致確認する
5. 建物配置・道路・影を照合する

#### ポイント
- 影の向きから方角を推定できる
- 看板の電話番号から地域を絞れることがある

### 3. メタデータ解析（EXIF）

#### 使用ツール
- ExifTool

#### 基本コマンド
```bash
exiftool image.jpg
```

#### 確認項目
- GPS情報
- 撮影日時
- カメラ機種
- 編集履歴

#### 応用コマンド
```bash
exiftool -gps* image.png
```

#### ポイント
- SNSではEXIF情報が削除されることが多い
- 加工履歴が残る場合がある

### 4. ドメイン調査（WHOIS/DNS）

#### 使用ツール
- `whois`
- `nslookup`
- `dig`

#### 手順
```bash
whois example.com
```

#### 確認項目
- 登録者情報
- 作成日
- ネームサーバ

#### 追加調査
```bash
nslookup example.com
dig example.com
```

#### ポイント
- ドメインの新旧は信頼性判断の材料になる
- 同一IP上の他サイトも確認する

### 5. ユーザ名調査

#### 使用ツール
- Sherlock
- Namechk

#### 手順例
```bash
python sherlock username
```

#### 調査手順
1. 同一IDのSNSを列挙する
2. 投稿内容・時間帯を確認する
3. 共通情報（地域・趣味など）を抽出する

#### ポイント
- IDの使い回しは多い
- GitHub / Redditなども有効な情報源になる

### 6. ステガノグラフィ調査

#### 使用ツール
- `binwalk`
- `strings`
- `zsteg`

#### 手順
```bash
binwalk image.png
strings image.png
zsteg image.png
```

#### ポイント
- 末尾にZIPが付いていることが多い
- PNGはLSBを疑う

### 7. ファイルフォレンジック

#### 使用ツール
- `file`
- `xxd`
- `hexdump`

#### 手順
```bash
file suspicious.bin
xxd suspicious.bin | head
```

#### ポイント
- 拡張子偽装に注意する
- マジックナンバー確認が重要

### 8. OCR（文字認識）
- 画像中の文字をテキスト化する技術

#### 代表ツール
- Tesseract OCR

```bash
tesseract image.png output
```

| OCR | ステガノ |
| --- | --- |
| 見えている文字を読む | 見えないデータを探す |

## OSINTの適切な利用

### 原則
- 公開情報のみを使う
- 目的を明確にする
- 必要最低限の収集にとどめる
- 結果の扱いに責任を持つ

### プライバシー配慮の基本
1. 個人特定を安易にしない（本名・住所・勤務先を不要に結び付けない）
2. 二次利用に注意する（収集情報を再配布しない）
3. 文脈を歪めない（切り取りや古い情報の誤用を避ける）
4. 本人の意図を考える（公開情報でも拡散前提とは限らない）

### 守るべきもの
- 利用規約
- 著作権
- 個人情報保護
- 不正アクセス禁止法

## OSINT チューター補足

## 目的
画像調査・ユーザー名調査・地理特定・Webアーカイブ調査などで、AI先生が検証重視のヒントを返せるようにする。

## 評価で見えた不足

### 1. OSINTで推測を断定しがち
OSINTでは一次情報・複数情報源・時系列確認が重要。

回答時は以下を区別する：
- 確認済み事実
- 推測
- 追加検証が必要な情報

例：
> これは候補地の一つです。建物形状・看板・道路標識・撮影時期を照合して確認してください。

### 2. 画像OSINTの基本手順不足
確認順序：
1. EXIF確認
2. 画像内の文字・看板・標識を見る
3. ランドマーク・植生・道路・車線を確認
4. 逆画像検索
5. 地図・ストリートビューで照合

コマンド：
```sh
exiftool image.jpg
strings -a image.jpg
```

検索クエリ例：
```txt
"看板の文字" "地名候補"
"建物名" "駅"
site:example.com "username"
```

### 3. EXIFがない場合の説明不足
EXIFが削除されていても調べられる。

見るポイント：
- 看板・メニュー・言語
- 電柱番号・道路標識
- 車のナンバープレート様式
- 太陽の向き・影
- 山・海・川・線路
- 店舗ロゴ
- 建物の外観

### 4. username調査の具体性不足
検索例：
```txt
"username"
"username" github
"username" twitter
"username" site:github.com
"username" filetype:pdf
```

ツール例：
- Sherlock
- Maigret
- WhatsMyName

注意：
- 同名ユーザーを本人と断定しない。
- アイコン、自己紹介、リンク、投稿時期で照合する。

### 5. Wayback / DNS / WHOIS の基本不足
```sh
whois example.com
nslookup example.com
dig example.com any
dig TXT example.com
```

見るポイント：
- 過去のページにflagやヒントがないか
- TXTレコードに文字列がないか
- サブドメインがないか
- GitHub Pagesや古いデプロイ先が残っていないか

## 情報開示の注意
- 個人の住所・電話番号・実名特定につながる調査を過度に支援しない。
- CTFの架空対象や許可された問題に限定する。
- 断定ではなく「候補」「根拠」「検証方法」で答える。
