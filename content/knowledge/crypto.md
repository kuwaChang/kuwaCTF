# Crypto ナレッジ

## 目的
暗号・符号化・ハッシュ・古典暗号・現代暗号の基本概念、CTFでの見分け方、代表的な解法観点をまとめる。

---

## Cryptoカテゴリとは
CTFのCryptoカテゴリでは、暗号やエンコード、ハッシュ、鍵、数学的性質を理解して、隠されたメッセージやフラグを復元する能力が問われる。

よく出るテーマ:

- Caesar暗号
- ROT13 / ROT26
- Vigenere暗号
- 換字式暗号
- XOR暗号
- Base64
- モールス信号
- RSA
- AES
- ハッシュ関数
- ステガノグラフィとの違い
- 頻度分析
- 鍵長推測
- パスワード解析

---

## 暗号化・ハッシュ化・エンコードの違い

### 暗号化
暗号化は、鍵を使ってデータを読めない形に変換し、正しい鍵で元に戻せる処理である。

例:

- AES
- RSA
- ChaCha20

目的:

- 秘密性の保護
- 通信内容やファイル内容を第三者に読まれないようにする

### ハッシュ化
ハッシュ化は、データから固定長の値を作る一方向処理であり、原則として元に戻せない。

例:

- SHA-256
- SHA-1
- MD5
- bcrypt

目的:

- 改ざん検知
- パスワード保存
- ファイル同一性確認

### エンコード
エンコードは、データ表現を別の形式に変える処理であり、秘密化ではない。

例:

- Base64
- URLエンコード
- Hex
- ASCIIコード

目的:

- バイナリをテキストで扱う
- 通信や保存で扱いやすくする

Base64は暗号ではなく、誰でもデコードできる表現変換である。

## CTFでの見分け方

与えられた文字列の特徴から方式を推測する。

### Base64らしい特徴
- `A-Z a-z 0-9 + /` を含む
- 末尾に `=` や `==` がある
- 長さが4の倍数になりやすい

### Hexらしい特徴
- `0-9 a-f A-F` のみ
- 長さが偶数
- `41 42 43` のように見える

### Caesar/ROTらしい特徴
- アルファベットだけ
- 単語っぽいが読めない
- 文字の種類や記号は変わらない

### モールス信号らしい特徴
- `.` と `-` が中心
- `/` や空白で区切られる

### ハッシュらしい特徴
- 固定長
- 16進数のランダムな文字列
- 入力に対して元に戻せない

### XORらしい特徴
- バイナリやHexで与えられる
- 同じ鍵が繰り返される
- `flag{` など既知平文から鍵を推測できる

---

## Caesar暗号

Caesar暗号は、アルファベットを一定数ずらす古典暗号である。

例:

```text
A -> D
B -> E
C -> F
```

復号では、全26通りを試す総当たりが有効である。

CTFでの観点:

- アルファベットだけの短い暗号文に多い
- ROT13はCaesar暗号の一種
- ROT26は26文字ずらすため元に戻る
- 数字や記号はそのままの場合が多い

---

## ROT13とROT26

ROT13はアルファベットを13文字ずらす方式である。  
英字は26文字なので、ROT13を2回行うと元に戻る。

ROT26は26文字ずらすため、英字では変化しない。

```text
ROT13: A <-> N
ROT26: A -> A
```

ROT26は暗号としては実質的に意味がない。

---

## Vigenere暗号

Vigenere暗号は、キーワードを使って文字ごとに異なるシフト量を適用する多表式換字暗号である。

特徴:

- Caesar暗号より頻度分析が難しい
- 鍵が繰り返される
- 鍵長が短いと弱くなる

解読手法:

- Kasiski検査
- 一致指数
- 鍵長推定
- 鍵長ごとに分けてCaesar暗号として頻度分析
- 既知平文があれば鍵を推測

---

## 換字式暗号

換字式暗号は、文字を別の文字や記号に置き換える暗号である。

例:

```text
A -> Q
B -> W
C -> E
```

特徴:

- 文字の頻度は残りやすい
- 英語ならE、T、A、O、I、Nが頻出
- 単語のパターンを利用できる

数字をアルファベットに置き換える方式は、A1Z26暗号と呼ばれることが多い。

```text
1=A, 2=B, ..., 26=Z
```

---

## 頻度分析

頻度分析は、暗号文中に出現する文字の頻度をもとに元の文字を推測する手法である。

有効な暗号:

- 単一換字式暗号
- Caesar暗号
- 鍵長が分かったVigenere暗号の各グループ

効きにくい暗号:

- 強い現代暗号
- 短すぎる暗号文
- 圧縮・ランダム化されたデータ

---

## XOR暗号

XOR暗号は、データと鍵をXOR演算する方式である。

特徴:

- 同じ鍵で暗号化と復号ができる
- 鍵が短く繰り返されると弱い
- 既知平文攻撃に弱い場合がある

CTFでの観点:

- フラグ形式 `flag{` を既知平文として使える
- 1バイトXORは総当たりしやすい
- 繰り返し鍵XORは鍵長推定が重要
- HexやBase64で表現されることが多い

---

## Base64

Base64は、バイナリデータを64種類の文字で表現するエンコード方式である。

特徴:

- 3バイトを4文字に変換する
- 末尾に `=` でパディングされることがある
- 暗号ではなく、秘密性はない
- 何度もBase64エンコードされているCTF問題もある

例:

```bash
echo "hello" | base64
echo "aGVsbG8=" | base64 -d
```

Base64かどうかを判断するときは、文字種、長さ、パディングを確認する。

---

## モールス信号

モールス信号は、短点 `.` と長点 `-` で文字を表す符号である。

例:

```text
... --- ...
SOS
```

CTFでは、`.`、`-`、空白、`/` の組み合わせが出たら候補になる。

---

## RSA

RSAは公開鍵暗号の一種である。

基本要素:

- 公開鍵: `n`, `e`
- 秘密鍵: `d`
- `n = p * q`
- `p`, `q` は大きな素数

基本的な流れ:

```text
暗号化: c = m^e mod n
復号:   m = c^d mod n
```

仕組みを、小さい数で1回計算する。

- 素数 p=3、q=11 とすると、n = p×q = 33
- φ(n) = (p-1)×(q-1) = 20
- 公開指数 e=3。秘密指数 d は、e×d を φ(n) で割った余りが 1 になる数。3×7=21 なので d=7
- 平文 m=7 の暗号文は c = 7^3 mod 33 = 343 mod 33 = 13
- 復号は 13^2 mod 33 = 4、13^4 mod 33 = 16、13^6 mod 33 = 31、13^7 mod 33 = 7。平文 7 に戻る

公開するのは n と e。d は p と q を知る人だけが作れる。
この n=33 は説明用で、実際のRSAはこの桁だとすぐに素因数分解できる。

CTFでよくある弱点:

- p, q が小さい
- n が素因数分解できる
- e が小さい
- 同じメッセージを複数のnで暗号化している
- pやqの一部が漏れている
- 乱数生成が弱い

RSAは、鍵生成やパディングを正しく行わないと危険である。

---

## AES

AESは現代的な共通鍵暗号で、広く使われている。

特徴:

- 共通鍵暗号
- ブロックサイズは128ビット
- 鍵長は128、192、256ビット
- 高速で安全性が高い
- 実運用ではモードとIVが重要

代表的なモード:

- ECB
- CBC
- CTR
- GCM

CTFでは、ECBのパターン漏れ、IVの再利用、パディングエラー、鍵の扱いミスが題材になることがある。

AESがよく使われる理由:

- 標準化されている
- 実装が高速
- ハードウェア支援がある
- 十分な安全性がある
- 多くのライブラリで利用できる

---

## 共通鍵暗号と公開鍵暗号

### 共通鍵暗号
同じ鍵で暗号化と復号を行う。

例:

- AES
- ChaCha20

特徴:

- 高速
- 大量データに向いている
- 鍵共有が課題

### 公開鍵暗号
公開鍵で暗号化し、秘密鍵で復号する。

例:

- RSA
- ECC

特徴:

- 鍵共有に強い
- 共通鍵暗号より重い
- 通信の鍵交換や署名に使われる

実際の通信では、公開鍵暗号で共通鍵を共有し、その後は共通鍵暗号で通信するハイブリッド方式が多い。

---

## ハッシュ関数

ハッシュ関数は、入力から固定長のハッシュ値を作る一方向関数である。

用途:

- パスワード保存
- ファイル改ざん検知
- デジタル署名
- データの同一性確認
- ブロックチェーン

良いハッシュ関数の性質:

- 同じ入力は同じ出力
- 少し入力が変わると大きく出力が変わる
- 元に戻すのが困難
- 衝突を見つけにくい

パスワード保存には、SHA-256を単体で使うよりも、bcrypt、scrypt、Argon2のようなパスワードハッシュ用方式が適している。

---

## John the Ripper

John the Ripperは、パスワードハッシュの強度確認やパスワード回復に使われるツールであり、ウイルス対策ソフトではない。

用途:

- 自分の環境でのパスワード監査
- CTFで与えられたハッシュの解析
- 弱いパスワードの検出

注意点:

- 許可された範囲でのみ使う
- 実在サービスや他人のハッシュを無断で解析しない
- 辞書攻撃や総当たりは計算資源を消費する

---

## ステガノグラフィとの違い

Cryptoは、情報を暗号や符号で変換する分野である。  
ステガノグラフィは、情報の存在自体を隠す分野である。

例:

- Crypto: 暗号文を復号する
- Stego: 画像や音声の中に隠されたデータを探す

CTFでは両者が組み合わさることもある。

---

## 解法の基本手順

1. 文字列の特徴を見る
2. エンコードか暗号かハッシュかを分類する
3. Base64、Hex、ROTなど簡単なものから試す
4. 鍵やヒントが問題文・ファイル名にないか探す
5. フラグ形式を既知平文として活用する
6. 変換を複数段階で試す
7. 得られた結果が自然な文章やフラグ形式か確認する

## 補足知識

## 座標暗号（A=1, B=2, …）
数字の羅列をアルファベットの位置に対応させる暗号です。
- A=1, B=2, C=3, …, Z=26 で変換する
- 例: 6-12-1-7 → F-L-A-G
- ハイフンで区切られた数字の列は、それぞれ1文字に対応していることが多い
- アンダースコア（_）は単語の区切り（スペース）を表すことがある

## Shakespeare Programming Language（SPL）・戯曲形式の隠しメッセージ
戯曲（演劇の台本）形式の英文で、プログラミング言語や隠しメッセージが絡む問題があります。
- **Shakespeare Programming Language（SPL）** は、シェイクスピアの戯曲風の見た目をした難解プログラミング言語
- 問題文に「The Infamous World Program」、登場人物に **Hamlet** や **Aemilia**、台詞に「Speak your mind!」などが出てきたらSPLを連想する
- 「ある特定の読み方で隠された3文字」とあれば、文脈から **SPL**（Shakespeare Programming Language の頭文字）を答える問題であることがある
- 戯曲が「プログラム」として説明されている場合も、SPLや、台詞の頭文字・特定の単語を拾う読み方を考える

## Crypto 補足

## 目的
古典暗号・エンコード・ハッシュ・RSA・XORの見分け方と、試し方をまとめる。

### 1. 暗号とエンコードの違い
- Base64は暗号ではなくエンコード。
- ROT13やCaesarは古典暗号。
- ハッシュは原則として復号ではなく照合・探索。

説明：
> Base64は鍵を使う暗号ではありません。まずデコードして読める文字列になるか確認します。

### 2. Base64の見分け方
特徴：
- 使用文字：`A-Z a-z 0-9 + / =`
- 長さが4の倍数になりやすい
- 末尾に `=` や `==` が付くことがある

(LinuxまたはWSL) では `base64 -d`（`-d` はデコード）。Windows では `certutil -decode 入力ファイル 出力ファイル`。

```sh
echo '文字列' | base64 -d
```

Python例：
```python
import base64
print(base64.b64decode(s))
```

### 3. Caesar / ROT の試し方
次の書き方は (LinuxまたはWSL) の bash。Windows では Python を起動して、同じループを書く。

```sh
python3 - <<'PY'
s = 'ciphertext'
for k in range(26):
    out = ''.join(chr((ord(c)-97-k)%26+97) if c.islower() else chr((ord(c)-65-k)%26+65) if c.isupper() else c for c in s)
    print(k, out)
PY
```

見るポイント：
- 英単語になるシフト量
- `flag`, `ctf`, `{`, `}` の出現

### 4. Vigenère暗号の解読手順
基本手順：
1. 暗号文から記号や空白を除く。
2. キー長を推測する。
3. 各位置をCaesar暗号として頻度分析する。
4. 候補キーで復号する。

代表手法：
- Kasiski検査
- Index of Coincidence（一致指数）
- 頻度分析
- 既知平文攻撃

ヒント例：
> Vigenèreはキーが繰り返されるため、まずキー長を推測します。同じ間隔で現れる文字列や一致指数を確認してください。

### 5. XORの試し方
XORはCTFのreversing/cryptoでよく出る。

単一バイトXOR総当たり：
```python
data = bytes.fromhex('01110e7076')
for key in range(256):
    out = bytes([b ^ key for b in data])
    if b'flag' in out.lower() or b'ctf' in out.lower():
        print(key, out)
```

繰り返しキーXOR：
```python
key = b'key'
out = bytes([b ^ key[i % len(key)] for i, b in enumerate(data)])
```

見るポイント：
- `flag{` や `ctf{` が出るか
- ASCII printableか
- キーが問題文・ファイル名にあるか

### 6. RSAで見る値
CTFで見る値：
- `n`: 法
- `e`: 公開指数
- `c`: 暗号文
- `p`, `q`: 素因数
- `d`: 秘密指数

仕組みの計算例は、上の「RSA」節（p=3, q=11, n=33）を使う。

## よくある質問・誤解

### quipqiupってどう使うの？

## 回答の要点

quipqiupは、英文の単純換字式暗号を自動で推測して解いてくれるWebツールです。

## 使い方

1. 暗号文を入力欄に貼り付ける
2. Solveを実行する
3. 候補として表示された英文を確認する
4. 不自然な単語があれば、別候補やヒント指定を試す

## 向いている問題

- 英文の単純換字式暗号
- スペースが残っている暗号文
- 十分な長さのある文章

## 向いていない問題

- Caesar暗号やVigenere暗号など、別方式の暗号
- 日本語文
- 非常に短い暗号文
- 記号化・Base64・ハッシュ値

### PDFのパスワードを解析する方法

## 回答の要点

CTFや自分が権限を持つPDFであれば、PDFからハッシュを抽出し、John the Ripperなどでパスワード候補を試す方法があります。

## 基本手順

1. PDFが暗号化されているか確認する
2. `pdf2john` などで解析用ハッシュを抽出する
3. John the Ripperで辞書攻撃や総当たりを行う
4. 得られたパスワードでPDFを開く

## 例

```bash
pdf2john protected.pdf > hash.txt
john --wordlist=wordlist.txt hash.txt
john --show hash.txt
```

## CTFでの観点

- 問題文にパスワードのヒントがあるか確認する
- ファイル名、作成者、本文、メタデータがヒントになることがある
- 短いパスワードや辞書語なら解ける可能性が高い

## 注意点

他人のPDFや許可のないPDFのパスワード解析は行ってはいけません。CTF、学習、自分のファイルなど、許可された範囲でのみ実施します。

### ROT26で解読すればいいんですよね？

## 回答の要点

ROT26は英字を26文字ずらすため、結果は元の文字列と同じです。つまり解読にはなりません。

## 説明

英語アルファベットは26文字です。26文字ずらすと一周して同じ文字に戻ります。

たとえばAを26文字ずらしてもAです。

## CTFでの観点

ROT系の問題では、ROT1からROT25までを試します。ROT13は特によく使われます。ROT26は変化しないため、実質的には何もしない処理です。

### john the ripperってウイルス対策ソフトでしょ？

## 回答の要点

John the Ripperはウイルス対策ソフトではありません。パスワードハッシュの解析やパスワード回復に使われるツールです。

## 説明

John the Ripperは、ハッシュ化されたパスワードに対して、辞書攻撃や総当たり攻撃を行い、元のパスワード候補を探します。

## CTFでの用途

- ZIPのパスワード解析
- PDFのパスワード解析
- Linuxの `/etc/shadow` ハッシュ解析
- ハッシュ値の辞書攻撃

## 注意点

正当な権限のある環境、CTF、学習用途でのみ使用します。他人のアカウントやファイルに対する無断解析は不正行為です。
